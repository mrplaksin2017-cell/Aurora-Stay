# Aurora Stay — веб-прототип онлайн-бронирования

Статическая веб-версия комплекса «Онлайн-бронирование». Интерфейс сделан на чистом HTML, CSS и JavaScript, поэтому его можно открыть напрямую через `index.html` или запустить из PyCharm без установки зависимостей.

## Что уже работает

- адаптивная главная страница для экранов от мобильного до desktop;
- поиск по городу, датам и количеству гостей;
- фильтры по категории отеля и сортировка по цене;
- карточки отелей с демо-данными из предметной модели (Hotel, RoomType, Room);
- подробные карточки отелей: описание, рейтинг, отзывы, удобства и правила отмены;
- форма бронирования с расчётом количества ночей и итоговой суммы;
- подтверждение бронирования и хранение демо-броней в `localStorage`;
- раздел «Мои бронирования» с отменой активной брони и демонстрационный вход в личный кабинет;
- избранные отели с сохранением между открытиями страницы;
- информационные блоки «Как это работает», факты о сервисе и раскрывающийся FAQ;
- сортировка по цене и рейтингу, фильтрация по категории и поиск по направлению.
- каталог всех 20 стран и 63 городов из SQL-структуры с быстрым выбором направления.
- расширенный seed: минимум 3 отеля в каждом городе и минимум 3 номера в каждом отеле;
- плавное появление секций и карточек при прокрутке, scroll-progress, hover-анимации и анимация модальных окон;
- поддержка `prefers-reduced-motion` для пользователей, которым нужны минимальные эффекты.

## Запуск

1. Открой папку `travel` в PyCharm.
2. Открой `index.html` в браузере (или запусти встроенный preview).

Сейчас это front-end прототип: данные из SQL Server представлены в `database-data.js` как временный seed для браузера. Скрипт `SQLQuery4_ExpandCatalog.sql` расширяет реальную БД до 3 отелей на город и 3 номеров на отель. Для подключения серверной части замените seed на запрос к REST API и отправляйте форму из `bookingForm` на endpoint создания Booking/Payment.

## Основа модели

Экран учитывает сущности из ER-модели: `Country → City → Hotel → RoomType → Room`, а также `User → Booking → Payment`. Реальная авторизация, платёжный шлюз и блокировка двойного бронирования должны быть реализованы на общем API для web, desktop и mobile клиентов.
